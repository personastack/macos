## Confirmed findings

1. A duplicate launch selects the first matching bundle process, including the invisible crash supervisor. The real app remains hidden. Regression reproduced for both regular and accessory app activation. Repair skips prohibited and terminated applications.
2. Crash retry can find an already running replacement without adopting the normal launch lifecycle. It never schedules the stable-runtime reset and reads the PID list twice. Regression reproduced the missing stability timer. Repair adopts one observed PID through the existing launch handler.
3. Download destination always reuses the suggested filename. Apple's installed WKDownloadDelegate contract requires a nonexistent destination, so a repeated filename fails. Repaired with bounded collision suffixes, basename confinement, dangling-link checks and filesystem filename-length limits. Three focused tests passed.
4. The user supplied the 01:28 DYLD crash from the temporary local candidate. Its missing Frameworks runpath was repaired before the earlier installation. Fresh installed readback confirms the runpath, Sparkle binary, valid signature and diagnostic startup exit 0. Added a shared pre-signing dependency check to reject the same missing runpath or framework before any signing operation. Normal signature-continuity fixtures without Sparkle remain supported. This does not establish GUI permissions or remote-control acceptance.
5. Local message rejection kept `busy` set and reused the rejected turn as a follow-up. Worker turn failure disabled the entire connected session. Rejected Stop remained stuck on Stopping. Reproduced all three failures, then repaired request tracking and shared turn cleanup. Added stale-turn protection and verified rejected follow-ups preserve the active turn. The worker protocol and cloud contracts are unchanged.
6. Local native commands always wrote stdin EOF after startup, even when a short command had already exited. This replaced its actual exit status with 126. Reproduced with `exit 7`. Repaired terminal-state handling and the exit/EOF race.
7. Worker stdin supports 256 KiB but native forwarded it as one write to a 32 KiB shell input boundary. The write failed and left the process running. Reproduced with a 75,000-byte input. Native now validates the worker bound, writes bounded chunks and cleans up failed commands.
8. Cancellation during shell startup could spawn a process and throw before returning its execution ID. Its caller had no ID to clean up. Reproduced with a bounded owned sleep process. The shared shell owner now cleans up failed startup independent of the cancelled task/deadline. Local command errors after startup use that cleanup too.
9. The main WebView ignored `shouldPerformDownload`, although the hosted attachment owner creates blob anchors with a download attribute. Displayable attachments could navigate instead of saving. Main and floating chat now share an explicit-download decision for the selected origin and its blobs. The floating chat also now uses the collision-safe destination owner from finding 3. External links retain their existing routing.
10. The native WebSocket used Foundation's default 1 MiB receive limit while the API/Gateway contract permits 8 MiB and native file patches support 4 MiB content. Valid large edits could terminate the connection before dispatch. Reproduced the limit on a real suspended URLSession task with no network traffic. Socket construction now sets the shared 8 MiB contract limit before resume and retains exact endpoint binding and machine authentication.

11. Local socket writes ran synchronously under the connection-state lock. A stalled worker blocked Close and incoming event delivery. A kernel fixture reproduced a 10.004-second Close delay. Writes now use one bounded serial queue off the caller thread. Read/write operations own close-on-exec descriptor duplicates, so shutdown can interrupt I/O without descriptor-reuse races. Queue or I/O failure closes the stream and drives existing session cleanup.
12. The main WebView passed arbitrary link/popup URL schemes to NSWorkspace, including local file URLs and non-browser handlers. Four cases reproduced this routing. Main and popout owners now share the web/email external-launch allowlist. Local files and other handlers are cancelled. Normal web navigation, in-page resources, explicit downloads and Google OAuth remain supported. URLs with embedded credentials cannot enter the external/OAuth paths.

13. Line-range reads checked cancellation before scanning but not between chunks. A cancelled distant-line read kept scanning the file and occupied the filesystem actor. A deterministic regression read a second chunk and returned success after cancellation. Scans now check cancellation and the admitted deadline between file chunks, directory entries and content lines. Patch reads preserve cancellation instead of mapping it to a content mismatch. These are cooperative checks; they cannot interrupt an OS syscall already in progress.

14. Failed manual Local Network, Notifications, and Launch at Login retries returned without opening the relevant macOS Settings pane. Fixed the explicit-retry paths and added coverage that automatic setup still does not open Settings. This makes denied or failed setup actionable; it does not make an unsigned build eligible for stable Local Network identity or Launch at Login registration.

15. Locked-control installation succeeded through the policy write but failed verification. macOS `authd` omits the user-class `allow-root` field from an `evaluate-mechanisms` readback. Both our installer and app rejected that legitimate readback. The shared verifier now accepts absence or explicit false while rejecting true and malformed values. A normalizing fake reproduced `.verificationFailed` before repair. A read-only probe of the actual installed policy now passes with the repaired shared contract. The existing signed helper and pin were valid. The earlier signature-failure diagnosis was incorrect.
16. Finish Setup opened a separate helper package. Eric requires our component to be part of the main install. The signed main package now contains the app and helper. Homebrew and Sparkle select that same package. Native setup offers read-only Verify Installation and an inline main-installer recovery message. Unsigned builds report their signing limitation before any helper installation. The app no longer bundles the separate helper package.
