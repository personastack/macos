## macOS pitfalls and failure rules

- `AXIsProcessTrustedWithOptions`, CoreGraphics preflight and actual AX/capture behavior can disagree after a change. Preserve the shared trust-and-role fallback and use a real relaunch only when needed. A reset manufactures more stale-cache states.
- An active prompt may outlive a task cancellation. Settle continuations once, cancel owned work, fence late success, and never start the next prompt after the window closes. Do not attempt to auto-click Apple's approvals using CUA.
- ScreenCaptureKit metadata queries can prompt. Keep them out of ordinary status, startup, heartbeats and passive polling. The private-picker dialog does not mean PersonaStack enabled audio; retain `capturesAudio = false`.
- Safari Automation is target-specific. Accessibility, FDA, and an Automation entitlement do not grant it. Safari JS and Remote Automation are different settings. An already-open browser can lose process-scoped verification after restart.
- General clipboard `.ask` and a successful user paste are not unattended Always Allow. Do not require a nonexistent Settings pane just because the SDK exposes an API on that OS.
- Network timeout, TLS failure and no Bonjour peers are not proof of denied consent. Nor is cloud success proof of LAN approval. Avoid automatic prompt loops on offline Macs.
- The stable Developer ID identity, host/child responsibility chain, bundle location, and actual launching process matter. Preserve current GHA signing and CUA embedded attribution. Do not grant broad access to Terminal as a workaround.
- Full Disk Access does not authorize root execution, grant all target-app Apple Events, unlock Keychain items, bypass SIP/ACLs, or guarantee access to all future app APIs. Handle those operation-specific boundaries honestly.
- Perfect prediction of renewed macOS consent is unavailable for some operations. Completion means verified supported capabilities and no known missing setup approval. It does not promise that Apple can never request consent again. Known missing approvals must block new work; uncertain operation outcomes must not be replayed.
