## OpenClaw dispatch agent

Login-helper startup resolves the supported home-local CLI bins and both macOS Homebrew prefixes without shell initialization. The pinned npm entrypoint uses `env node`. Its child PATH starts with a supported resolved Node interpreter. Official installer wrappers remain executable wrappers and retain their captured absolute Node. The selected user identity and native profile selectors are set explicitly. Missing or unsupported interpreters remain unavailable. No runtime installation or shell profile mutation occurs. See [startup source contracts](internal/openclawsetup/README.md).

Native discovery reads configured `agents.entries` or the supported `agents.list` shape from the selected profile. A sole agent is selected automatically. Several agents require the native picker. A config with neither roster property exposes the pinned upstream implicit `main` agent. Explicit empty, invalid or ambiguous rosters never fall back to `main`. The selected opaque candidate binds the physical profile and config snapshot. Preparation and enrollment reject stale choices before exchange or persistence. The helper stores the exact selected agent and validates its presence before configuration, effective catalog checks and dispatch. The API continues to select the physical profile. Agents do not create separate persona targets. [OpenClaw agent configuration](https://docs.openclaw.ai/gateway/config-agents)

## OpenClaw MCP Apps and no-model readiness

The supported path uses the pinned Gateway's MCP Apps capability. Native setup asks for per-profile Apps approval separately from gateway start or restart approval. The private Repair receipt also pins the exact observed connection generation and API target-selection revision. Ordinary installation, ConfigRefresh and Check cannot grant Apps permission. A missing flag returns `mcp_apps_disabled`, including when the selected gateway is stopped.

Apps approval changes only the selected profile's `mcp.apps.enabled` value and its exactly owned PersonaStack MCP entry. It preserves other keys. The helper accepts the upstream default bind or explicit `gateway.bind: "loopback"`. It refuses lan, custom, auto and malformed settings before writing. A running gateway must also prove that every selected-port listener address is numeric loopback on the same attributed PID. CLI bind overrides cannot substitute a matching config/profile for this evidence. When the configured port is unused, a bounded current-user listener scan must also exclude the selected physical profile on another CLI-overridden port. Distinct sibling profiles remain available. Helper-started gateways explicitly pass `--bind loopback` because the native default can depend on the launch environment. Apps enables HTML App capabilities. The pinned upstream starts an additional local sandbox listener when Apps is enabled. That listener inherits Gateway bind hosts. Existing sandbox settings stay unchanged. A configured non-loopback bind must be changed through the native runtime owner. Stopping it alone cannot make Repair enable Apps. The Apps flag stays enabled after disconnect as a user-selected profile feature. Config reload may require a selected gateway restart. A profile with reload disabled requires a manual selected-gateway restart before discovery can succeed.

Consented Repair retains a bounded pending setup flag in the existing binding. The normal reconciler completes it after the scoped gateway is available. It calls `sessions.create` with an explicit helper-owned key, selected agent and idempotency key. It omits message, task, attachments, title source and model overrides. The returned `runStarted` must be false. It then calls `mcp.app.discover`, reads `sessions.describe`, checks `tools.effective` and reads the same metadata again. Generation, target, admission and configuration checks guard saving the returned session key, ID and optional lifecycle revision. No model run is used for readiness.

Ordinary Check uses the retained session identity. It only reads metadata and effective tools after selected-profile authentication and process ownership checks. A reset identity, foreign agent, denied tool or cold/stale catalog prevents Ready. Static `tools.catalog` is capability description only. A direct PersonaStack initialize/tools-list handshake runs only after native effective access succeeds.

Assigned dispatch derives a separate helper-owned key from the exact API conversation and issued MCP namespace within the selected agent and binding. Missing conversation IDs use the existing assignment scope. The same no-model create/discover/effective checks precede the `agent` call. Submission carries that exact session key and the native `expectedExistingSessionId` plus lifecycle revision when supplied. This native admission fence prevents dispatch into a reset session. It does not promise atomic tool-policy snapshots. Native transcript continuity does not replace the API's durable conversation or composed-prompt authority.

## Hermes shared-host support boundary

Pinned Hermes enforces one native gateway host per OS user. Named standalone gateway startup is a retired compatibility path. A default gateway serves live nonparked profiles and activates sibling messaging and scheduled jobs. Native setup asks for that host-wide effect separately from selected-profile MCP repair. The private `hermes_host_confirmed` flag must accompany the exact approved connection generation and target revision. Pairing, migration and generic repair consent never grant host startup. Disconnect removes the selected owned MCP entry and binding. It does not stop the shared gateway.

The helper launches the supported default CLI profile explicitly. `HERMES_HOME` alone cannot defeat a sticky `active_profile` for the default root. The gateway parser accepts `gateway run` and has no `--port` option. Effective port/key resolution follows `gateway.platforms.api_server`, `platforms.api_server`, then `gateway.api_server`. Authored `extra` fields retain precedence over flat fields. A usable profile `.env` API key enables the native environment override pass. Stopped-host setup preserves existing literal keys, loopback host and custom port. Named profiles receive only their own API key. Their listener settings do not select the shared host.

The current input subset is literal YAML with bounded depth and no aliases or duplicate keys. Root `api_server` shorthand, legacy `gateway.json`, applicable managed policy directories, external `secrets` sources, interpolated values and quoted dotenv values refuse before host writes. Invalid dotenv integer ports also refuse. Native Hermes would ignore an invalid integer and retain its YAML value. This deliberate supported-input limit avoids guessing effective credentials or bind policy. The helper does not rewrite these unsupported configurations.

The owner reads the native current-user host rendezvous. The launch home’s literal `.env` lock-directory and XDG overrides take precedence over inherited values. A native control `identify` response must match the rendezvous PID, incarnation and canonical default home. The OS listener must be loopback on that same current-user PID. The selected named profile must appear in the native served-profile roster. A missing selected listener is insufficient to prove a stopped host. Live rendezvous ownership or a bounded current-user native gateway process scan refuses startup. Named-launched hosts and unresolved supervisors remain manual setup boundaries. No helper registry, host takeover, scheduler mutation or full-host restart exists.

At this pin `/v1/toolsets` lists configurable core/plugin toolsets and omits ordinary discovered MCP server toolsets. `hermes tools list --platform api_server` prints configured MCP entries and filter text. Native startup catches MCP discovery errors and can still serve the API. Neither output nor a config modification time proves an installed gateway loaded the issued server. Hermes readiness therefore means configured, authenticated and control-ready. The existing verifier requires the exact owned selected-profile MCP entry, permitted API MCP toolset policy and an authorized direct initialize/initialized/tools-list handshake. The direct catalog must contain `my_persona_info` and `baseline_prompt`. `tell_persona` is conditional on stack membership and is not required for a standalone persona. Protocol2025-11-25 uses the MCP producer’s unpaginated catalog. Normal Check does not change config or submit a model run. OpenClaw retains its stronger native effective-session proof.

This Hermes contract does not prove that the running gateway discovered or can invoke the issued MCP server. Source fixtures prove configured readiness and profile-scoped assigned submission only. Signed installed-runtime acceptance must send an assigned wake and observe an actual authorized PersonaStack MCP tool invocation. A failed native tool invocation remains a release blocker.
