# targetruntime

Resolve loopback endpoints from the selected native config. Prove listener UID and exact runtime/config/state attribution before attachment. Ports with foreign or ambiguous ownership return runtime_conflict. Pure endpoint and process-evidence fixtures cover attribution without spawning native services.

Pinned OpenClaw sets the macOS gateway process title to exactly `openclaw-gateway` ([run-loop.ts](https://github.com/openclaw/openclaw/blob/8420f82cbbf8bd0114cacc39fa51299f92851a6f/src/cli/gateway-cli/run-loop.ts#L71-L75)). That title identifies the runtime but never authorizes attachment. After `lsof` selects one listener PID and `ps` proves the current UID, Darwin `KERN_PROCARGS2` supplies that PID's original environment. The bounded parser separates argv from environment and returns only exact `OPENCLAW_STATE_DIR` and `OPENCLAW_CONFIG_PATH` fields. Missing, foreign, duplicate or inaccessible fields fail closed. Raw argv/environment is neither logged nor persisted.

An actual bounded macOS Node title-mutation check confirmed that `ps eww` drops environment output while `KERN_PROCARGS2` retains both dummy profile fields. Source fixtures pin that producer shape and wrong UID/root/config denial. A Darwin-only in-process test reads its own test PID to cover the native syscall boundary. These checks do not prove installed OpenClaw runtime readiness.

An existing gateway installed with plain `openclaw gateway install` may omit both profile environment fields. The pinned [service environment producer](https://github.com/openclaw/openclaw/blob/8420f82cbbf8bd0114cacc39fa51299f92851a6f/src/daemon/service-env.ts#L349-L355) copies them only when present. Such a listener returns `runtime_conflict` even when its UID and gateway title match. `HOME`, the service label and a health response cannot prove its effective config. OpenClaw [loads global dotenv values before config resolution](https://github.com/openclaw/openclaw/blob/8420f82cbbf8bd0114cacc39fa51299f92851a6f/src/cli/run-main.ts#L910-L918), so absent launch selectors do not authorize guessed paths.

Helper-started gateways set both exact absolute profile fields. Native installs with explicit `--profile default` or `--profile work` also [set both fields when absent](https://github.com/openclaw/openclaw/blob/8420f82cbbf8bd0114cacc39fa51299f92851a6f/src/cli/profile.ts#L127-L140). For the standard default service, the user can explicitly run `openclaw --profile default gateway install --force` through OpenClaw to refresh its definition. Alternatively the user can stop the preexisting gateway through its native owner, then choose PersonaStack Repair and approve starting the selected profile. PersonaStack does not stop or rewrite an unattributed preexisting service. Custom wrappers and unresolved profile selectors remain unsupported until exact native profile evidence is available.

The selected-port `lsof -nP -Fpn` record proves actual bind addresses before PID/profile attribution. Every listener must have a numeric loopback address and the same PID. IPv4 and IPv6 records for the same PID are valid. Wildcards, LAN addresses, missing descriptors/names, malformed fields and other PIDs fail closed. This check runs before OpenClaw Apps Repair writes and during ordinary attachment. The native CLI [chooses explicit --bind before config and uses an environment-dependent default](https://github.com/openclaw/openclaw/blob/8420f82cbbf8bd0114cacc39fa51299f92851a6f/src/cli/gateway-cli/run.ts). Helper launch explicitly sets `--bind loopback`. The checks do not promise atomicity with later user-owned process changes.

Field-format evidence is the installed macOS `/usr/share/man/man8/lsof.8` section “OUTPUT FOR OTHER PROGRAMS”. It specifies newline termination, process `p` records, always-selected descriptor `f` records and selected name/Internet-address `n` records. The fixtures pin `p812\nf21\nn127.0.0.1:25907\n` and dual-stack equivalents. No native service was started to obtain this evidence.

A configured port with no listener does not prove a stopped OpenClaw profile. Before treating it as stopped, the owner scans current-user TCP LISTEN PIDs across ports. It checks exact native runtime/UID and kernel profile selectors. Known distinct physical profiles are ignored. A selected profile on another port, missing scope or a symlink/hardlink alias is refused before Apps writes. The scan is ephemeral. It is bounded to 128 PIDs, 64 KiB per command and the five-second owner-probe deadline. It never records arbitrary process arguments or environment values.

Hermes ownership uses its producer-owned current-user host rendezvous and native control `identify` response. Both must agree on PID, start fingerprint and canonical default home. The actual loopback API listener must belong to that same current-user native gateway. Named profiles must be in its served-profile roster. Profile API paths are `/p/default/` or `/p/<name>/`. The launch home’s literal `.env` lock-directory/XDG values override inherited values. Live foreign homes, named-launched hosts, missing socket evidence, wildcard listeners and API-disabled live hosts refuse attachment and startup. Listener absence also requires a bounded current-user gateway scan before treating the native host as stopped. No host takeover or restart exists.
